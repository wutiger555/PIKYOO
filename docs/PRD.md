## 1. 產品概述

### 1.1 一句話
**PIKYOO 匹友是雙北匹克球的課程媒合平台：學生（自己或揪朋友）五分鐘找到適合的教練並預約，教練有一個能被搜到、能收預約的招生頁與管理後台。揪團打球、找場是輔助功能。**

> 2026-09 方向調整：以「課程」為主軸。底部導覽改為 首頁／找教練／我的課／我的；揪團球局降為首頁下方的次要入口（功能保留）。

### 1.2 產品定位
| | |
|---|---|
| 核心使用者 | 學生（個人，或揪朋友一起上課的小團體）、教練；團主（揪團打球）為次要 |
| 核心價值 | 學生：用照片、認證、匹克球檔案與價格比較教練，一頁完成預約；朋友可以各自用帳號加入同一堂小班課、各自付款。教練：有一個好看、能被搜到的招生頁，課程方案、時段、預約與收款集中管理。團主：開團不用再手動接龍（次要） |
| 主要入口 | Google 搜尋（SEO）、LINE 群組分享的球局卡片、PIKYOO 官方帳號圖文選單 |
| 與競品差異 | LINE 原生體驗 + AI 一貼成局 + 課程預約 + 新手路徑 + 出席信用（詳見 PLAN.md §4） |

### 1.3 MVP 目標（上線後 8 週）
| 目標 | 指標 |
|---|---|
| 團主願意用 PIKYOO 取代接龍 | 30 位活躍團主、每週 100 個球局、滿團率 ≥ 60% |
| 教練願意把課放上來 | 30 位教練上架、每週 50 筆課程預約申請 |
| 新手找得到、留得住 | 新手完成第一次報名的轉換率 ≥ 15%、4 週留存 ≥ 25% |

### 1.4 非目標（MVP 不做）
- 線上付款（Phase 3 接藍新平台金流，見 PLAN.md §12）
- 球館完整場地租借行事曆
- 原生 App（Phase 4，承接團隊既有的 App 上架經驗）
- 一對一聊天室：學生問教練改用教練頁的「問與答」（F3-11），預約後的訊息串排在 Phase 2；LINE 官方帳號只做通知，不公開教練的私人 LINE
- 雙北以外地區的資料營運（系統支援，但不主動建置資料）

## 2. 使用者與情境

### 2.1 使用者角色
| 角色 | MVP | 說明 |
|---|---|---|
| 玩家 Player | ✅ | 找局、報名、找課、預約、找場 |
| 團主 Host | ✅ | 任何玩家都可以開團，開過團即具團主身分 |
| 教練 Coach | ✅ | 申請並經審核後，取得教練頁與課程管理 |
| 場館 Venue | ⚪ 資料由我們建置 | Phase 3 才開放場館帳號上架時段 |
| 管理員 Admin | ✅ | 內部營運後台 |

### 2.2 人物誌（Persona）

**小安｜新手**
29 歲上班族，被同事帶去打過一次，覺得好玩，但不知道去哪上課，也怕程度太差跟不上別人。
→ 需要：「新手友善」的課與局、清楚的價格與地點、不用下載 App。

**阿凱｜團主**
38 歲，管 3 個 LINE 群組共約 400 人，每週開 4 局。每次都要手動接龍、處理有人臨時取消、遞補、放鳥。
→ 需要：開團快、名單自動更新、候補自動遞補、知道誰常放鳥。

**Mia｜教練**
32 歲，網球轉匹克球，有協會教練認證，在 2 個場館授課。招生靠 IG 和朋友介紹，排課靠 LINE 私訊。
→ 需要：一個好看、能被搜到的招生頁；學生能直接選時段預約；預約集中管理。

### 2.3 現況使用者旅程：大家現在怎麼找教練、找學生、找局

**學生找教練（現況：FB 社團 / Threads / IG）**
```text
在 Threads 發文「大台北有推薦的匹克球教練嗎？新手小白」
  → 等留言（數小時～數天）
  → 收到 10+ 則留言：教練自我推薦、朋友推薦、球館廣告，資訊格式各不相同
  → 一個個點進 IG / FB 看，價格多半沒寫
  → 私訊詢問價格、時間、地點（每位教練重問一次）
  → 被導到 LINE 加好友，再來回確認時段
  → 轉帳付款、截圖回傳
```
**痛點：** 慢、資訊不透明（價格、程度、地點）、品質參差不齊、無法比較、無法確認教練資格、全程要打字。

**教練招生（現況）**
```text
Threads / IG 發文與限動 → 在 FB 社團回覆「有推薦教練嗎」的貼文 → 私訊一個個回答同樣的問題
→ LINE 排時間 → 手動記名單、對帳
```
**痛點：** 曝光靠運氣、重複回答、排課與收款都是手工、沒有可以「放在個人簡介的連結」直接預約。

**玩家找局（現況：LINE 群組接龍）**
```text
群組內看到接龍 → 複製貼上加名字 → 訊息被洗掉 → 臨時有人退出 → 團主手動找人補
```

**PIKYOO 的做法：不取代社群，而是成為社群貼文的「落地頁」。**
- 教練照樣在 Threads / IG / FB 經營聲量，但貼文與個人簡介放的是 **PIKYOO 教練頁連結**，點進來就能看到標準化資訊、直接選時段預約。
- 團主照樣在 LINE 群組揪人，但貼的是 **PIKYOO 球局卡片**，點進來一鍵報名。
- 學生不用再發文等留言：在 PIKYOO 用 **標準化的教練卡** 比較價格、程度、地點、認證與評價。

### 2.4 核心情境
1. **週五晚上，小安在 Google 搜「台北 匹克球 新手課」** → 進到 PIKYOO 課程頁 → 用 LINE 登入 → 預約 Mia 週日的體驗課。
2. **阿凱把平常的揪團文字貼到 PIKYOO** → AI 解析成球局 → 分享卡片到 3 個 LINE 群組 → 群友點卡片直接報名 → 有人取消時，候補自動遞補並收到 LINE 通知。
3. **小安上完體驗課** → PIKYOO 推薦「本週新手友善球局」→ 報名阿凱的局 → 成為常客。

## 3. 平台架構

### 3.1 一套程式碼、三種入口
```text
                 ┌───────────────────────────────────────┐
                 │   PIKYOO Web（Next.js，響應式）          │
                 │   自有帳號系統與資料（Supabase）          │
                 │   API-first：未來原生 App 共用同一套 API   │
                 └───────────────────┬───────────────────┘
       ┌─────────────────────────────┼─────────────────────────────┐
  ① 瀏覽器（手機 / 桌機）        ② LINE 內開啟（LIFF → MINI App）     ③ 原生 App（Phase 4）
  ‣ Google 搜尋進站（SEO）        ‣ 自動 LINE 登入                    ‣ 承接團隊既有 App 上架經驗
  ‣ 桌機版給教練管理用            ‣ 分享球局卡片到群組                 ‣ Expo / React Native
  ‣ 可加到主畫面（PWA）           ‣ 官方帳號圖文選單入口               ‣ 共用 API 與型別
```

### 3.2 LINE 整合規格
| 項目 | MVP 做法 | 備註 |
|---|---|---|
| LINE Login | 建立 LINE Login channel；LINE 內自動登入，瀏覽器內走 OAuth | 同時支援 Email（magic link）登入，避免綁死 LINE |
| LIFF | 同一個 Next.js 網站註冊為 LIFF app（Full 尺寸）；偵測 `liff.isInClient()` 切換行為 | 每個 channel 最多 30 個 LIFF app，MVP 用 1 個 |
| 分享到群組 | `liff.shareTargetPicker()` 分享 **Flex Message 球局卡片**（標題、時間、地點、程度、剩餘名額、報名按鈕） | 需在 console 啟用 shareTargetPicker；瀏覽器內退回為複製連結 + OG 預覽圖 |
| 官方帳號 | 「PIKYOO 匹友」官方帳號；圖文選單：找球局／開團／找教練／我的 | 先用輕用量（免費 200 則），依推播量升級 |
| 推播 | Messaging API Push：只用在高價值通知（見 §5.6） | Reply API 免費；推播依收件人數計費 |
| MINI App | Phase 1.5 將 LIFF 申請為 **未認證 MINI App**（台灣可直接發佈）；Phase 2 視成效申請認證 | LINE 官方已宣布 LIFF 將併入 MINI App；需確認台灣 MINI App「服務訊息」通知是否可降低推播成本 |

### 3.3 響應式斷點
| 斷點 | 寬度 | 主要使用者 |
|---|---|---|
| Mobile | 360–767 | 玩家（主要）、LIFF 內 |
| Tablet | 768–1199 | — |
| Desktop | ≥ 1200 | 教練後台、管理後台、SEO 進站 |

> **設計原則：Mobile-first。** 90% 以上的玩家流量預期在手機與 LINE 內。

### 3.4 手機優先體驗原則（Mobile UX Principles）
玩家幾乎都是「在 LINE 群組看到 → 手機點開 → 單手操作」。每個畫面都要符合以下原則：

| # | 原則 | 具體規格 |
|---|---|---|
| M1 | **單手、拇指區操作** | 主要行動按鈕固定在畫面底部（Sticky CTA：「報名｜NT$150」「預約這堂課」）；底部 Tab；篩選用 Bottom Sheet，不用頂部下拉選單 |
| M2 | **時間優先** | 玩家的第一個問題是「什麼時候」→ 列表以日期分組，卡片左側大字顯示時間；快速篩選 Chips：今天／明天／週末／晚上／新手友善 |
| M3 | **三次點擊內完成** | 從 LINE 卡片 → 報名完成 ≤ 3 次點擊（開啟 → 報名 → 確認）；LINE 內自動登入，不跳出登入頁 |
| M4 | **幾乎不用打字** | AI 一貼成局；日期時間用滾輪 / 快捷選項；記住上次的場地與設定；「複製上一團」 |
| M5 | **一眼看懂狀態** | 名額用座位圖示（●●●○ 缺 1）；程度用固定色階徽章；狀態用顏色 + 文字雙重表達（不只靠顏色） |
| M6 | **跳出去的都要能回來** | 導航開 Google / Apple Maps；「加入行事曆」（Google / iOS）；LINE 分享後回到原頁；深層連結直達指定球局或課程 |
| M7 | **快** | Skeleton loading；報名採樂觀更新（先顯示成功，後端失敗再回滾）；圖片 lazy load；LINE 內建瀏覽器實測 |
| M8 | **大字友善** | 內文 16px 起、支援系統字級放大不破版、點擊區 ≥ 44px（中高齡玩家比例高） |
| M9 | **可分享到任何社群** | 球局與課程都能產生 LINE Flex 卡片、OG 預覽、以及 IG / Threads 限動尺寸（1080×1920）分享圖 |
| M10 | **桌機是加分，不是縮放** | 桌機版給教練後台、管理後台與 SEO 訪客：多欄佈局、表格化管理，而不是把手機版放大 |

**設計參考（互動模式，非視覺）：** LINE（台灣人最熟悉的操作語言）、Google Maps（地點與導航）、inline 訂位（極短預約流程）、Playtomic / Reclub（球局與場地卡片資訊密度）、Threads（輕量、以內容為主）。

## 5. 功能規格（MVP）

### 5.1 F1 帳號與個人檔案
| ID | 使用者故事 | 優先 | 驗收條件 |
|---|---|---|---|
| F1-1 | 身為玩家，我想用 LINE 一鍵登入 | P0 | LINE 內 0 點擊自動登入；瀏覽器內 ≤ 2 步；首次登入帶入 LINE 暱稱與頭像 |
| F1-2 | 身為玩家，我想用 Email 登入 | P1 | Magic link 登入；可事後綁定 LINE |
| F1-3 | 首次登入時簡單設定檔案 | P0 | 3 步內完成：暱稱 → 程度（自評或「我是新手」）→ 常打區域（雙北行政區多選）；可略過 |
| F1-4 | 查看與編輯個人檔案 | P0 | 顯示：頭像、暱稱、程度、常打區域、打球次數、出席率（僅本人可見明細） |
| F1-5 | 刪除帳號 | P0 | 個資法要求；刪除後個資匿名化、球局紀錄保留為「已刪除使用者」 |
| F1-6 | 通知設定 | P1 | 可分別開關 LINE／Email 通知類型 |

**程度制度：** 採 2.0–5.0（0.5 級距），與 DUPR 常見區間對齊，另加「新手（未滿 2.0）」。MVP 為自評 + 團主回饋，不串 DUPR API。

### 5.2 F2 球局（Games）— 核心模組
| ID | 使用者故事 | 優先 | 驗收條件 |
|---|---|---|---|
| F2-1 | 瀏覽球局列表 | P0 | 預設「今天起、我常打的區域」；卡片顯示：時間、場地、程度、名額狀態（視覺化座位）、費用、新手友善標記 |
| F2-2 | 篩選球局 | P0 | 區域、日期（今天／明天／週末／自選）、時段（早／午／晚）、程度、新手友善、有空位 |
| F2-3 | 查看球局詳情 | P0 | 時間、場地（連到球場頁與地圖）、程度範圍、名額、費用與付款方式（現場／轉帳，純文字）、團主資訊、備註、參加名單（頭像 + 暱稱）、候補人數 |
| F2-4 | 報名球局 | P0 | 一鍵報名；未登入先登入後自動回到報名；程度不在範圍內顯示提醒（不阻擋，除非團主設定「嚴格程度」） |
| F2-5 | 額滿時加入候補 | P0 | 顯示候補順位；有人取消時依序遞補並通知（規則見 §6.2） |
| F2-6 | 取消報名 | P0 | 取消期限前免責取消；期限後取消記為「晚取消」 |
| F2-7 | 開團：表單 | P0 | 欄位：日期、開始／結束時間、場地（從球場資料庫搜尋，或自填地點）、程度範圍、總名額、團主是否佔名額、費用、取消期限（預設 12 小時前）、新手友善、備註 |
| F2-8 | 開團：AI 一貼成局 | P0 | 貼上文字 → 3 秒內產生預填表單；辨識不確定的欄位以黃色標示請使用者確認；場地模糊比對球場資料庫；解析失敗退回空白表單並保留原文 |
| F2-9 | 分享到 LINE 群組 | P0 | LIFF 內用 shareTargetPicker 發 Flex 卡片；瀏覽器內複製連結，連結具 OG 預覽圖（動態顯示剩餘名額） |
| F2-10 | 團主管理球局 | P0 | 編輯資訊（已報名者會收到變更通知）、移除參加者、手動加人（非 PIKYOO 使用者可用「代報名：暱稱」）、取消球局（全員通知） |
| F2-11 | 團主點名 | P1 | 球局結束後 48 小時內標記「出席／未到」；未標記不計入出席率 |
| F2-12 | 複製上一團 | P1 | 從歷史球局一鍵複製成新的一團（日期自動 +7 天） |
| F2-13 | 週期性開團 | P2 | 每週固定自動開團 |
| F2-14 | 團主回饋程度 | P2 | 點名時可選填「程度偏高／符合／偏低」，用於校準 |

**AI 一貼成局：解析規格**
```text
輸入：自由文字（中文為主，含 emoji、換行、LINE 接龍格式）
輸出（JSON）：
  date, start_time, end_time, venue_text, venue_id?（比對結果）,
  level_min, level_max, capacity, spots_left?, fee, fee_note,
  beginner_friendly, notes, confidence{每個欄位 0–1}
範例輸入：
  「🔥週六 3/8 14:00-16:00 大安運動中心 2.5-3.0 缺2 每人150 現場付 新手勿入」
```

## 6. 規則與狀態

### 6.1 球局狀態
```text
open（招募中） ──額滿──▶ full（額滿，可候補）
   ▲                      │
   └────有人取消（且無候補）─┘
open / full ──開始時間到──▶ in_progress ──結束時間到──▶ completed
open / full ──團主取消──▶ cancelled
```

### 6.2 參加者狀態與候補規則
```text
joined（已報名） / waitlisted（候補，含順位） / cancelled（已取消） / late_cancelled（晚取消）
completed 後由團主標記：attended（出席） / no_show（未到）
```
- 有人取消 → 候補第 1 位**自動遞補**為 joined，並發 LINE 通知。
- 若距開始 **< 3 小時** 才遞補：改為「遞補邀請」，需在 30 分鐘內確認，逾時換下一位。
- 取消期限由團主設定（預設開始前 12 小時）；期限後取消記為 late_cancelled。

### 6.3 課程預約狀態
```text
pending（待確認） ──教練確認──▶ confirmed ──上課後──▶ attended / no_show
pending ──教練婉拒 / 48 小時未處理自動取消──▶ declined / expired
confirmed ──學生依規則取消──▶ cancelled
```

## 13. 風險與對策

| 風險 | 對策 |
|---|---|
| 團主不想改變接龍習慣 | AI 一貼成局讓開團比接龍更快；分享卡片直接在原本的 LINE 群組運作 |
| 教練上架意願低 | BD 一對一協助建頁；教練頁本身就是免費的 SEO 招生頁 |
| AI 解析錯誤造成錯誤資訊 | 一律預覽確認後才發布；低信心欄位強制確認 |
| LIFF / MINI App 規格變動 | 核心功能不依賴 LINE 專屬 API；瀏覽器版完整可用 |
| LINE 推播成本失控 | 通知分級，只有高價值事件走 LINE；每月監控則數 |
| 放鳥紀錄引發爭議 | 不公開、可申訴、團主只看摘要 |
