## 0. TL;DR（一頁結論）

1. **市場是真的，但「整合平台」這個位置已經不是空的。** 台灣至少有 8 個以上的匹克球找場／揪團產品在 2025–2026 年上線，其中 **PickleTown 匹克城** 已有原生 App、DUPR 整合、球館 SaaS，並自稱 12,000+ 使用者。原計劃書的「Courts + Coaches + Classes + Games 一站整合」在功能上與它高度重疊。
2. **但還沒有贏家品牌。** 各平台的資料量、活動量都偏低（例如某平台全台只有 39 個活躍球局、另一平台「找活動」頁是空的），實際的揪團仍然發生在 LINE 群組與 FB 社團。市場處於「很多人在做、沒人做透」的碎片化階段 → 機會仍在，但窗口大約只剩 12–18 個月。
3. **不要做第 9 個球場地圖。** 球場目錄已是 commodity，不能當差異化。建議 PIKYOO 的切入點改為：
   - **(A) 團主與教練的工具**（先有單機價值，不依賴網路效應）
   - **(B) 新手入坑第一站**（成長最快的族群，且最沒人照顧）
   - **(C) LINE 友善 + AI 原生**（不用下載 App、LINE 一鍵登入與分享；把 LINE 貼文一貼就變成可報名的球局）
4. **小團隊 + AI 開發是可行的**，前提是：一套 Web 程式碼（同時支援瀏覽器、LINE 內開啟、PWA）、不做原生 App、平台不經手資金、MVP 範圍砍到 6–8 週可上線。真正的瓶頸不是寫程式，而是 **社群營運與 B 端（教練／團主）開發**，這部分 AI 取代不了，需要至少 1 人專職。

## 2. 台灣匹克球市場現況（2026/09）

### 2.1 規模與成長
- 打球人口約 **20 萬人**，媒體稱年增逾 8 成；業界樂觀預估年底上看百萬（此數字偏行銷，保守看待）。
- 全台球場約 **150–300 處**（不同平台統計口徑不同：156、138、200+、300+），一年內成長逾 8 成，但熱門時段仍「搶不到場」。
- 各縣市正在積極新建／改建場地（例：台北景美河濱 2026/03 改為羽球 + 匹克共用場）。

### 2.2 價格帶（台北民營球館為例）
| 項目 | 價格 |
|---|---|
| 包場 | NT$1,000–1,200 / 小時 |
| Open Play（臨打） | NT$200–350 / 人 |
| 新手團體課 | NT$500 / 人起 |
| 球局分攤（揪團） | NT$80–400 / 人 |

→ 金流主要在 **場租** 與 **課程**，揪團本身客單價低。

### 2.3 族群
- **新手佔大宗**：年增 8 成代表每年有一半以上的人是新手；有教練一個月帶 100+ 位新學員。
- **轉項者**：網球、羽球、桌球玩家轉入。
- **高消費族群**：EMBA、企業主、主管圈正在流行（有校際 EMBA 巡迴），是品牌贊助與企業團建的潛在客群。
- 年齡層廣（8–80 歲），中高齡比例高 → **介面要簡單、LINE 登入、字要大**。

### 2.4 生態結構
- **揪團仍然發生在 LINE 群組 / LINE 社群 / FB 社團**（數百到數萬人的群組）。痛點：接龍名單手動維護、候補混亂、放鳥、程度不符、資訊被洗掉。
- **公立場地** 採「開放預約日 +7」搶場制度；**民營球館** 各自用 TinyBook、PickleBook、官方 LINE 或 IG 公告。
- **DUPR** 在台灣快速普及，已有固定 DUPR 積分賽、TMLP 聯賽；2026 年 DUPR 開始接受 AI 影片分析（PB Vision 等）產生評分。
- **中華民國匹克球協會** 有認證教練名單與找球場頁面，但不是產品化的服務。

### 3.1 競品地圖

| 競品 | 類型 | 主要功能 | 規模／活躍度 | 強項 | 弱點 |
|---|---|---|---|---|---|
| **PickleTown 匹克城** | 原生 App + Web | 找場、揪團、社團、聊天、DUPR 整合、Round Robin 產生器；B 端 PickleBook 球館預約/金流 | 自稱 700+ 球場、12,000+ 使用者、2,000+ 場次；2026/01 上架、迭代快（v1.6.3） | **最強直接競品**：功能最完整、有 B 端收入 | 需下載 App；App Store 評分數極少；偏進階玩家/DUPR；教練/課程非重點 |

| **Picklemaster TW** | Web（內容站） | 156 球場目錄、規則教學、裝備 | SEO 流量型 | 內容／SEO | 無互動功能 |
| **揪in** | Web + LINE Bot | 開團報名連結、自動候補、LINE 群組 +1 | 1,200+ 場開團 | **團主工具做得好**、LINE 原生 | 跨運動、無匹克球專屬內容 |
| **ShareJoin 誰揪 / GRASS** | 綜合運動 App | 揪團、共享器材、教練目錄 | 14,790 場館（體育署資料） | 資料量大 | 非匹克球專屬、淺 |
| **Reclub** | 國際 App | 俱樂部與球局管理 | 香港、越南非常活躍 | 國際網路效應 | 台灣尚未普及，但**隨時可能進來** |
| **SP Pickleball Club** | 教練/課程品牌站 | 雙北課程、私教、企業團建 | 區域型 | 真的有在賣課 | 單一品牌，不是平台 |
| **協會官網** | 官方 | 認證教練名單、找球場 | — | 權威性 | 非產品化 |

### 3.2 觀察
1. **球場目錄 = 紅海**：至少 6 家在做，資料大同小異。PIKYOO 必須有球場資料，但不能以它為賣點。
2. **揪團 = 工具戰 + LINE 戰**：成功的是嵌入 LINE 的工具（揪in、小幫手），而不是要求使用者搬家的平台。
3. **教練 / 課程 = 相對藍海**：目前只有協會名單、個別教練品牌站、綜合平台的淺層目錄。**沒有人把「新手找體驗課 → 報名 → 上完課後找新手局」這條路做順**。而這條路上有真實金流（課程費）。
4. **信任 / 可靠度 = 沒人做**：放鳥、程度不符是每個團主的抱怨，但沒有平台處理「出席信用」。
5. **AI = 沒人真正用**：競品都是傳統 CRUD 產品。

## 4. 差異化策略

### 4.1 定位（修正版）

> **PIKYOO 匹友 — 讓團主和教練最好用、讓新手最放心的匹克球入口。**
> 「開團、招生，一貼就好；想打球，來這裡就對了。」

原本 tagline「Find your court. Find your coach. Find your game.」可保留為品牌長期標語；對外溝通的切入訊息改為**新手與團主**視角。

### 4.2 五個差異化支柱

| # | 支柱 | 具體做法 | 為什麼競品難跟 |
|---|---|---|---|
| 1 | **LINE 原生，不用下載 App** | LINE Login、LIFF 網頁、球局卡片可分享到 LINE 群組（名單即時更新）、LINE 通知提醒 | PickleTown 是 App-first，要轉向成本高 |
| 2 | **AI 一貼成局（團主工具）** | 團主把平常在 LINE/FB 貼的文字（「週六 14:00 大安運動中心 2.5–3.0 缺 2」）貼進來 → AI 自動解析成結構化球局 + 報名連結 + 自動候補 | 零學習成本；同時是我們的**資料取得引擎**（冷啟動解法） |
| 3 | **新手入坑路徑（Beginner Journey）** | 「我是新手」專區：程度自評 → 附近體驗課 → 新手友善球局 → 裝備建議；新手友善認證的團主/教練 | 成長最快的族群；教練有付費動機，形成收入 |
| 4 | **匹友信用（出席與程度可信度）** | 出席率、準時率、團主回饋的程度校準、「新手友善」徽章；放鳥紀錄對團主可見 | 需要累積資料，先做先贏；直接解決團主痛點 |
| 5 | **教練招生頁（Coach OS 雛形）** | 教練一分鐘建立個人頁 + 課程；學員詢問走 LINE；後續加入排課、點名、收款對帳 | 教練/課程目前無人產品化 |

### 4.3 策略原則：Come for the tool, stay for the network
- 冷啟動期，**團主與教練即使只有自己在用 PIKYOO，也有價值**（開團更快、名單不亂、招生頁好看）。
- 每一個團主/教練帶進他自己的 20–200 位球友 → 球友在 PIKYOO 看見其他球局與課程 → 網路效應。
- 目標：**先搞定 50 位團主 + 30 位教練**，而不是先搞定 1 萬個玩家。

### 4.4 刻意不做（至少 MVP 不做）
- ❌ 原生 App（iOS/Android）— Phase 4 才做，路線與進入條件見 §11.4–11.5、[APP.md](APP.md)
- ❌ 完整球館管理系統（與 PickleBook、TinyBook 硬碰）；改為「時段與課程的預約入口」，見 §12
- ❌ 平台自己收錢再撥款（資金過水）— 改用不過水的平台金流，見 §12
- ❌ 一對一聊天室 — 學生問教練改用教練頁的公開「問與答」（PRD F3-11），不公開教練的私人 LINE，避免學生和教練私下約課繞過平台；預約後的訊息串排在 Phase 2，看需求再做
- ❌ 自建 AI 影片分析（未來透過 DUPR 生態系合作夥伴整合）

## 6. 可行性評估（小團隊 + AI 開發）

### 6.1 技術可行性：✅ 高
- Next.js + Supabase（Postgres、Auth、RLS、Storage、Realtime）+ Vercel 是 AI 程式助理最熟悉的組合之一，產出品質穩定。
- 需補充：**LINE Login + LIFF**、**LINE Messaging API**（通知）、**LLM API**（一貼成局解析、搜尋）。
- 地圖：MVP 用 Google Maps（台灣使用者熟悉），控制 API 用量；或 MapLibre + OSM 零成本方案。
- PWA 即可達到「加到主畫面」的類 App 體驗。

### 6.2 營運可行性：⚠️ 中（真正的風險）
| 工作 | AI 可替代程度 | 說明 |
|---|---|---|
| 前後端開發、測試 | 高 | AI 為主、人審核 |
| UI 設計 | 中高 | 設計系統 + AI 生成，需人把關品牌感 |
| 球場資料建置 | 中高 | 體育署開放資料 + 公開資訊整理，AI 清洗；**不要爬競品資料** |
| 內容（新手指南、規則） | 中高 | AI 撰寫、人審核，同時做 SEO |
| 團主 / 教練開發（BD） | **低** | 需要人去球場、加群組、建立關係 |
| 社群營運、客服、糾紛 | **低** | 放鳥爭議、評價爭議需人處理 |

**建議人力：** 1 位產品/技術（帶 AI 開發）+ 1 位社群/BD（最好本身是球友或教練）。沒有社群/BD 角色的話，此專案成功率會大幅下降。

### 6.3 法規與風險
- **個資法**：收集手機、程度、出席紀錄 → 需隱私權政策、同意機制、刪除帳號功能。
- **金流**：平台自己收款再撥款（過水）涉及代收代付規範、信託、以及可能須就全額開立發票與繳營業稅；改採不過水模式後，平台只就「平台費」開發票。細節需與會計師確認，見 §12。
- **評價/信用系統**：避免公開羞辱式的放鳥標記，初期只對團主可見，並提供申訴。
- **商標/網域**：PIKYOO / 匹友 需查 TIPO 商標（第 9、35、41、42 類），並確認 pikyoo.com / .tw / .app 可註冊。

### 6.4 競爭風險
| 風險 | 機率 | 對策 |
|---|---|---|
| PickleTown 推出 LINE 版或教練功能 | 中 | 速度 + 專注新手/教練；在教練與團主關係上先卡位 |
| Reclub 等國際平台進入台灣 | 中 | 在地化（LINE、中文、在地教練網絡）是護城河 |
| 使用者不願離開 LINE 群組 | 高 | **不要求離開**：PIKYOO 是 LINE 群組的外掛，而不是替代品 |
| 資料冷啟動失敗 | 中 | 一貼成局 + 開放資料 + 手動建置雙北 100 個場地 |

## 7. 修正後的 MVP

### 7.1 核心驗證問題
> 「一位團主願不願意用 PIKYOO 取代 LINE 接龍？一位新手能不能在 PIKYOO 5 分鐘內找到一堂體驗課或新手局？」

### AI 開發工作方式
- 每個功能先寫 **簡短 spec（使用者故事 + 驗收條件）** → AI 實作 → 人工 review → 自動化測試。
- 資料庫 schema 與 RLS 規則由人主導設計，這是最不能出錯的地方。
- 維持單一 repo、單一部署目標，降低 AI 上下文複雜度。開始做原生 App 時，同一個 repo 改成 npm workspaces（`web/`、`app/`、`packages/core`），見 [APP.md](APP.md) §3。

## 11. 平台形式決策：Web / PWA / LINE / 原生 App

### 11.1 四種形式比較

| 面向 | 響應式 Web | PWA | LINE LIFF / MINI App | React Native（Expo） |
|---|---|---|---|---|
| AI 開發成本 | ⭐ 最低 | ⭐ 最低（Web + 設定） | 低（同一套 Web + LIFF SDK） | 中高（另一套 UI、兩個平台打包、上架審核） |
| 被搜尋到（SEO） | ✅ 最強：「台北 匹克球 教練」可直接搜到教練頁 | ✅ 同 Web | ❌ LINE 內頁面不被 Google 收錄 | ❌ 需另做網站 |
| 使用門檻 | 點連結就能用 | 點連結就能用，可加到主畫面 | LINE 內點連結即開、免註冊 | 需下載、註冊 |
| 登入 | Email / Google / LINE | 同 Web | LINE 自動登入（最順） | 皆可 |
| 分享到 LINE 群組 | 分享連結 | 分享連結 | ✅ 可直接挑群組分享卡片 | 分享連結 |
| 推播通知 | ❌ | ⚠️ Android 可；iOS 需先「加到主畫面」才可 | ✅ 透過官方帳號推播（有費用，見 11.3） | ✅ 最完整 |
| 上架審核 | 無 | 無 | 未認證 MINI App 台灣可直接發佈 | Apple / Google 審核，每次更新都要等 |
| 平台依賴風險 | 無 | 低 | ⚠️ 高：LINE Notify 已於 2025/03 終止；LIFF 正併入 MINI App | 中（Apple/Google 政策） |
| 固定成本 | 主機 | 主機 | 主機 + 官方帳號訊息費 | 主機 + Apple US$99/年 + Google US$25 |

### 11.2 決策：一套 Web 程式碼，三種入口

```text
                ┌─────────────────────────────┐
                │  PIKYOO Web（Next.js）       │
                │  自有帳號系統（Supabase）      │
                └──────────────┬──────────────┘
      ┌────────────────────────┼────────────────────────┐
  瀏覽器 / Google 搜尋        LINE 內開啟（LIFF）          加到主畫面（PWA）
  ‣ SEO：教練、課程、球場頁   ‣ LINE 一鍵登入             ‣ 類 App 體驗
  ‣ 新使用者主要來源         ‣ 分享球局卡片到群組         ‣ Web Push 通知
```

- **LINE 是「入口與通知管道」，不是平台。** 帳號、資料、金流都在 PIKYOO 自己手上；LINE Login 只是登入方式之一（另有 Email / Google）。LINE 若改政策，PIKYOO 不會被綁死。
- **為什麼不全押 LINE？** ① LINE 內頁面不會被 Google 收錄，而「搜教練、搜課程」正是我們的主戰場，需要 SEO；② LINE Notify 已停用、LIFF 正併入 MINI App，規格仍在變動；③ LINE 內建瀏覽器不能用 Google 登入。
- **為什麼不先做 React Native？** 對小團隊來說，兩套 UI、兩個商店審核、版本相容都會拖慢迭代。MVP 階段每週都要改東西，Web 可以即時上線。

### 11.3 LINE 商用版費用（2026/11/01 起新制）

| 方案 | 月費 | 內含推播則數 | 超量 |
|---|---|---|---|
| 輕用量 | NT$0 | 200 則 | 不可加購 |
| 中用量 | NT$1,000 | 3,000 則 | 需升級 |
| 高用量 | NT$1,400 | 6,000 則 | NT$0.2／則起，量大遞減 |

**不收費的：** LINE Login、LIFF、一對一聊天、自動回應、Messaging API 的 **Reply API**（使用者先傳訊息、我們回覆）、加好友歡迎訊息。
**收費的：** 主動推播（Push / 群發），且**按收件人數計算**（推 1 則給 5 人 = 5 則）。

**費用試算〔假設：每筆預約發 2 則 LINE 通知：確認 + 前一天提醒〕：**

| 每月預約數 | LINE 推播則數 | 方案 | 月費估計 |
|---|---|---|---|
| 100（封測） | 200 | 輕用量 | NT$0 |
| 1,000 | 2,000 | 中用量 | NT$1,000 |
| 5,000 | 10,000 | 高用量 + 4,000 則加購 | 約 NT$2,200 |
| 20,000 | 40,000 | 高用量 + 34,000 則加購 | 約 NT$8,200 |

**省錢策略：** 確認訊息顯示在網頁與 Email、只把「前一天提醒」「候補遞補成功」這類高價值通知走 LINE；PWA 使用者走免費的 Web Push。這樣大約可省一半。
→ **結論：LINE 費用不是負擔**。月 5,000 筆預約時通知費約 NT$2,000 上下，而同期平台費收入應遠高於此。

### 11.4 何時再做原生 App（觸發條件，符合任兩項才啟動）
- 週活躍使用者 > 5,000，且 iOS 使用者抱怨收不到通知
- 需要手機原生功能（場館 QR 報到、定位提醒、行事曆深度整合）
- 合作夥伴或投資人明確要求上架
- 屆時用 **Expo（React Native）** 重用 TypeScript 型別與 API 層；課程與場地屬於「實體服務」，依 Apple 審核指南 3.1.3(e) 可用第三方金流、不需走 Apple 內購抽成。
- 技術路線已決定，見 §11.5。

### 11.5 原生 App 路線（2026-10-04 決定）

Phase 4 做原生 App 時採 **React Native + Expo**，詳細架構、上架流程與維護規則見 [APP.md](APP.md)。

| 選項 | 結論 | 理由 |
|---|---|---|
| **React Native + Expo** | ✅ 採用 | 團隊上架過 RN；TypeScript 與網站同語言，可共用型別、Supabase 查詢、規則與假資料；EAS Update 小改免審核 |
| Capacitor（網站包成 App） | 備案 | 成本最低、BBC／Burger King 等在用，但團隊不熟，手感上限是網頁 |
| Flutter | ❌ | 新語言（Dart），與現有程式碼無法共用 |
| 原生 Swift + Kotlin | ❌ | 兩份程式碼，小團隊維護不了 |

- **打包上架**：初期用 Xcode／Android Studio 手動打包，不依賴 EAS 雲端打包；iOS 與 Android 同時上架。
- **範圍**：App 只做學員常用流程（找教練、預約、我的課程、揪團、通知）；教練後台與完整功能留在網頁。
- **進入條件**：§11.4 觸發條件符合任兩項，且 B1–B8 真資料穩定；公司開發者帳號（需 D-U-N-S）與自有網域就緒。
- **並存原則**：規則只寫一次（Supabase + `packages/core`），畫面各寫一份；資料庫只做加法以相容舊版 App。

## 12. 課程與場地預約整合 + 金流策略

### 12.1 為什麼這裡是突破口
- 目前 **沒有任何平台把「教練課程」產品化並可直接付款報名**（協會只有名單、SP Club 是單一品牌、綜合平台只有目錄）。
- 場地端各自為政：TinyBook、PickleBook、Google 表單、官方 LINE 私訊、IG 公告。雙北有大量 2025–2026 新開的小型球館，**沒有預約系統或系統很陽春**。
- 金流在這裡：新手課 NT$500 起、Open Play NT$200–350、包場 NT$1,000–1,200／小時。

### 12.2 場地整合分三層（逐步加深，不硬碰 PickleBook）

| 層級 | 做法 | 場館需付出的心力 | 時程 |
|---|---|---|---|
| L1 導流 | 場地頁清楚列出預約方式，一鍵跳到場館原本的系統或 LINE | 零 | MVP |
| L2 時段上架 | 合作場館在 PIKYOO 後台上架「可賣的東西」：Open Play 場次、體驗課、空檔時段；使用者直接報名付款 | 低（每週花 10 分鐘上架） | Phase 3 |
| L3 系統串接 | 與場館既有預約系統 API 或行事曆同步 | 中（需技術合作） | Phase 4 |

> 重點：PIKYOO 先賣「**場次**」（Open Play、課程、體驗），不做完整的「場地租借行事曆管理」。場次是標準商品、好上架、新手最需要；完整場管留給 PickleBook 等專門系統，未來再串接。

### 12.3 金流：三種模式比較

| 模式 | 說明 | 平台掌控度 | 維運／法規負擔 | 評估 |
|---|---|---|---|---|
| A. 不碰錢 | 教練自己收（轉帳、LINE Pay） | 低：不知道有沒有成交 | 零 | MVP 用 |
| **B. 平台金流「不過水」** | 教練／場館各自是金流商的收款方，錢直接進他們帳戶；平台發動交易並**自動代扣平台費** | **高**：結帳流程、訂單、抽成都在平台 | **低**：平台不經手資金，退款、爭議由收款方處理；平台只就平台費開發票 | ✅ **採用** |
| C. 平台代收再撥款（過水） | 平台收全額，定期撥給教練 | 最高 | **高**：代收代付規範、信託／履約保障、可能須全額開發票繳營業稅、每月對帳撥款 | ❌ 不採用 |

**選定：藍新 NewebPay 平台金流方案**（2026-10-04 重新比較六家後維持，備選改為統一金流 PAYUNi；完整比較見 [PAYMENTS.md](PAYMENTS.md)）
- 藍新提供針對媒合平台的「**平台金流模組**」，包含「平台商金流**不過水**（旗下收款方獨立金流服務，藍新金流直接入帳）」與「**代扣平台費用機制**」— 正好符合「掌控金流，但不用花力氣維運」。
- 支援信用卡、超商代碼、ATM 虛擬帳號、行動支付；無年費、無設定費。信用卡手續費約 2.8%（由收款方負擔或另議）。
- **備案：** 綠界 ECPay（手續費約 2.75%、功能最齊全），需確認其平台／分帳方案是否支援不過水 + 代扣平台費。
- **不選 Stripe：** 不支援超商代碼、ATM 等台灣習慣的付款方式。

**要準備的事：**
1. PIKYOO 需有 **公司登記** 才能簽平台金流合約。
2. 教練／場館需申請成為藍新收款方（個人或公司），**這是 onboarding 的主要摩擦** → 由 BD 協助開通，並保留模式 A 作為過渡。
3. 平台條款：取消／退款規則（例：48 小時前免費取消）、平台費比例、爭議處理流程。
4. 會計師確認：平台費發票開立方式、收款方的稅務責任說明。

### 12.4 預約流程（Phase 3 目標體驗）

```text
新手在 Google 搜「台北 匹克球 體驗課」
   → PIKYOO 課程頁（SEO）
   → 選時段 → LINE 一鍵登入
   → 付款（藍新：信用卡／超商／LINE Pay）
   → 錢直接進教練帳戶，平台自動扣 X% 平台費
   → LINE / Email 確認信 + 前一天提醒
   → 上完課 → 推薦「新手友善球局」→ 留在 PIKYOO
```
