# PIKYOO｜匹友 — 市場分析與產品計劃 v0.2

> 本文件以原始計劃書（v0.1）為基礎，加入 2026/09 台灣匹克球市場與競品調查、差異化策略、小團隊 + AI 開發的可行性評估，以及修正後的 MVP 與開發路線。
> 標記 **〔假設〕** 的數字尚未驗證，需在 Phase 0 訪談中確認。

---

## 0. TL;DR（一頁結論）

1. **市場是真的，但「整合平台」這個位置已經不是空的。** 台灣至少有 8 個以上的匹克球找場／揪團產品在 2025–2026 年上線，其中 **PickleTown 匹克城** 已有原生 App、DUPR 整合、球館 SaaS，並自稱 12,000+ 使用者。原計劃書的「Courts + Coaches + Classes + Games 一站整合」在功能上與它高度重疊。
2. **但還沒有贏家品牌。** 各平台的資料量、活動量都偏低（例如某平台全台只有 39 個活躍球局、另一平台「找活動」頁是空的），實際的揪團仍然發生在 LINE 群組與 FB 社團。市場處於「很多人在做、沒人做透」的碎片化階段 → 機會仍在，但窗口大約只剩 12–18 個月。
3. **不要做第 9 個球場地圖。** 球場目錄已是 commodity，不能當差異化。建議 PIKYOO 的切入點改為：
   - **(A) 團主與教練的工具**（先有單機價值，不依賴網路效應）
   - **(B) 新手入坑第一站**（成長最快的族群，且最沒人照顧）
   - **(C) LINE 原生 + AI 原生**（不用下載 App；把 LINE 貼文一貼就變成可報名的球局）
4. **小團隊 + AI 開發是可行的**，前提是：Web / LINE LIFF 優先、不做原生 App、不碰金流代收、MVP 範圍砍到 6–8 週可上線。真正的瓶頸不是寫程式，而是 **社群營運與 B 端（教練／團主）開發**，這部分 AI 取代不了，需要至少 1 人專職。

## 2. 台灣匹克球市場現況（2026/09）

### 2.1 規模與成長
- 打球人口約 **20 萬人**，媒體稱年增逾 8 成；業界樂觀預估年底上看百萬（此數字偏行銷，保守看待）。
- 全台球場約 **150–300 處**（不同平台統計口徑不同：156、138、200+、300+），一年內成長逾 8 成，但熱門時段仍「搶不到場」。
- 各縣市正在積極新建／改建場地（例：台北景美河濱 2026/03 改為羽球 + 匹克共用場）。

### 2.2 價格帶（台北民營球館為例）
| 項目 | 價格 |
|---|---|
| 包場 | NT$1,000–1,200 / 小時 |
| Open Play（臨打） | NT$200–350 / 人 |
| 新手團體課 | NT$500 / 人起 |
| 球局分攤（揪團） | NT$80–400 / 人 |

→ 金流主要在 **場租** 與 **課程**，揪團本身客單價低。

### 2.3 族群
- **新手佔大宗**：年增 8 成代表每年有一半以上的人是新手；有教練一個月帶 100+ 位新學員。
- **轉項者**：網球、羽球、桌球玩家轉入。
- **高消費族群**：EMBA、企業主、主管圈正在流行（有校際 EMBA 巡迴），是品牌贊助與企業團建的潛在客群。
- 年齡層廣（8–80 歲），中高齡比例高 → **介面要簡單、LINE 登入、字要大**。

### 2.4 生態結構
- **揪團仍然發生在 LINE 群組 / LINE 社群 / FB 社團**（數百到數萬人的群組）。痛點：接龍名單手動維護、候補混亂、放鳥、程度不符、資訊被洗掉。
- **公立場地** 採「開放預約日 +7」搶場制度；**民營球館** 各自用 TinyBook、PickleBook、官方 LINE 或 IG 公告。
- **DUPR** 在台灣快速普及，已有固定 DUPR 積分賽、TMLP 聯賽；2026 年 DUPR 開始接受 AI 影片分析（PB Vision 等）產生評分。
- **中華民國匹克球協會** 有認證教練名單與找球場頁面，但不是產品化的服務。

## 3. 競品分析

### 3.1 競品地圖

| 競品 | 類型 | 主要功能 | 規模／活躍度 | 強項 | 弱點 |
|---|---|---|---|---|---|
| **PickleTown 匹克城** | 原生 App + Web | 找場、揪團、社團、聊天、DUPR 整合、Round Robin 產生器；B 端 PickleBook 球館預約/金流 | 自稱 700+ 球場、12,000+ 使用者、2,000+ 場次；2026/01 上架、迭代快（v1.6.3） | **最強直接競品**：功能最完整、有 B 端收入 | 需下載 App；App Store 評分數極少；偏進階玩家/DUPR；教練/課程非重點 |
| **台灣匹克聚會所** picklejo.tw | Web | 場地地圖、揪團列表、DUPR 說明 | 138 場地、39 個活躍球局（集中台中） | 程度標籤、新手友善篩選 | 活動量少、區域集中、無交易 |
| **匹克球小幫手 / 中毒社群** ipickleball | Web + LINE | LINE 登入報名、賽事/DUPR 報名、場館後台 | 300+ 場館、賽事資訊多 | **賽事報名**是強項 | 「找活動」幾乎沒有活動 |
| **你來我網 RallyNow** | Web | 場地地圖、賽事、論壇、商店 | 200+ 場地 | 內容 + 電商 | 社群互動弱 |
| **Picklemaster TW** | Web（內容站） | 156 球場目錄、規則教學、裝備 | SEO 流量型 | 內容／SEO | 無互動功能 |
| **揪in** | Web + LINE Bot | 開團報名連結、自動候補、LINE 群組 +1 | 1,200+ 場開團 | **團主工具做得好**、LINE 原生 | 跨運動、無匹克球專屬內容 |
| **ShareJoin 誰揪 / GRASS** | 綜合運動 App | 揪團、共享器材、教練目錄 | 14,790 場館（體育署資料） | 資料量大 | 非匹克球專屬、淺 |
| **Reclub** | 國際 App | 俱樂部與球局管理 | 香港、越南非常活躍 | 國際網路效應 | 台灣尚未普及，但**隨時可能進來** |
| **SP Pickleball Club** | 教練/課程品牌站 | 雙北課程、私教、企業團建 | 區域型 | 真的有在賣課 | 單一品牌，不是平台 |
| **協會官網** | 官方 | 認證教練名單、找球場 | — | 權威性 | 非產品化 |

### 3.2 觀察
1. **球場目錄 = 紅海**：至少 6 家在做，資料大同小異。PIKYOO 必須有球場資料，但不能以它為賣點。
2. **揪團 = 工具戰 + LINE 戰**：成功的是嵌入 LINE 的工具（揪in、小幫手），而不是要求使用者搬家的平台。
3. **教練 / 課程 = 相對藍海**：目前只有協會名單、個別教練品牌站、綜合平台的淺層目錄。**沒有人把「新手找體驗課 → 報名 → 上完課後找新手局」這條路做順**。而這條路上有真實金流（課程費）。
4. **信任 / 可靠度 = 沒人做**：放鳥、程度不符是每個團主的抱怨，但沒有平台處理「出席信用」。
5. **AI = 沒人真正用**：競品都是傳統 CRUD 產品。

## 4. 差異化策略

### 4.1 定位（修正版）

> **PIKYOO 匹友 — 讓團主和教練最好用、讓新手最放心的匹克球入口。**
> 「開團、招生，一貼就好；想打球，來這裡就對了。」

原本 tagline「Find your court. Find your coach. Find your game.」可保留為品牌長期標語；對外溝通的切入訊息改為**新手與團主**視角。

### 4.2 五個差異化支柱

| # | 支柱 | 具體做法 | 為什麼競品難跟 |
|---|---|---|---|
| 1 | **LINE 原生，不用下載 App** | LINE Login、LIFF 網頁、球局卡片可分享到 LINE 群組（名單即時更新）、LINE 通知提醒 | PickleTown 是 App-first，要轉向成本高 |
| 2 | **AI 一貼成局（團主工具）** | 團主把平常在 LINE/FB 貼的文字（「週六 14:00 大安運動中心 2.5–3.0 缺 2」）貼進來 → AI 自動解析成結構化球局 + 報名連結 + 自動候補 | 零學習成本；同時是我們的**資料取得引擎**（冷啟動解法） |
| 3 | **新手入坑路徑（Beginner Journey）** | 「我是新手」專區：程度自評 → 附近體驗課 → 新手友善球局 → 裝備建議；新手友善認證的團主/教練 | 成長最快的族群；教練有付費動機，形成收入 |
| 4 | **匹友信用（出席與程度可信度）** | 出席率、準時率、團主回饋的程度校準、「新手友善」徽章；放鳥紀錄對團主可見 | 需要累積資料，先做先贏；直接解決團主痛點 |
| 5 | **教練招生頁（Coach OS 雛形）** | 教練一分鐘建立個人頁 + 課程；學員詢問走 LINE；後續加入排課、點名、收款對帳 | 教練/課程目前無人產品化 |

### 4.3 策略原則：Come for the tool, stay for the network
- 冷啟動期，**團主與教練即使只有自己在用 PIKYOO，也有價值**（開團更快、名單不亂、招生頁好看）。
- 每一個團主/教練帶進他自己的 20–200 位球友 → 球友在 PIKYOO 看見其他球局與課程 → 網路效應。
- 目標：**先搞定 50 位團主 + 30 位教練**，而不是先搞定 1 萬個玩家。

### 4.4 刻意不做（至少 MVP 不做）
- ❌ 原生 App（iOS/Android）
- ❌ 球館預約系統（與 PickleBook、TinyBook 硬碰；改為「連結到球館原本的預約方式」）
- ❌ 平台代收代付金流
- ❌ 自建聊天室（LINE 已經是聊天室）
- ❌ 自建 AI 影片分析（未來透過 DUPR 生態系合作夥伴整合）

## 6. 可行性評估（小團隊 + AI 開發）

### 6.1 技術可行性：✅ 高
- Next.js + Supabase（Postgres、Auth、RLS、Storage、Realtime）+ Vercel 是 AI 程式助理最熟悉的組合之一，產出品質穩定。
- 需補充：**LINE Login + LIFF**、**LINE Messaging API**（通知）、**LLM API**（一貼成局解析、搜尋）。
- 地圖：MVP 用 Google Maps（台灣使用者熟悉），控制 API 用量；或 MapLibre + OSM 零成本方案。
- PWA 即可達到「加到主畫面」的類 App 體驗。

### 6.2 營運可行性：⚠️ 中（真正的風險）
| 工作 | AI 可替代程度 | 說明 |
|---|---|---|
| 前後端開發、測試 | 高 | AI 為主、人審核 |
| UI 設計 | 中高 | 設計系統 + AI 生成，需人把關品牌感 |
| 球場資料建置 | 中高 | 體育署開放資料 + 公開資訊整理，AI 清洗；**不要爬競品資料** |
| 內容（新手指南、規則） | 中高 | AI 撰寫、人審核，同時做 SEO |
| 團主 / 教練開發（BD） | **低** | 需要人去球場、加群組、建立關係 |
| 社群營運、客服、糾紛 | **低** | 放鳥爭議、評價爭議需人處理 |

**建議人力：** 1 位產品/技術（帶 AI 開發）+ 1 位社群/BD（最好本身是球友或教練）。沒有社群/BD 角色的話，此專案成功率會大幅下降。

### 6.3 法規與風險
- **個資法**：收集手機、程度、出席紀錄 → 需隱私權政策、同意機制、刪除帳號功能。
- **金流**：平台代收代付涉及第三方支付規範，MVP 不碰。
- **評價/信用系統**：避免公開羞辱式的放鳥標記，初期只對團主可見，並提供申訴。
- **商標/網域**：PIKYOO / 匹友 需查 TIPO 商標（第 9、35、41、42 類），並確認 pikyoo.com / .tw / .app 可註冊。

### 6.4 競爭風險
| 風險 | 機率 | 對策 |
|---|---|---|
| PickleTown 推出 LINE 版或教練功能 | 中 | 速度 + 專注新手/教練；在教練與團主關係上先卡位 |
| Reclub 等國際平台進入台灣 | 中 | 在地化（LINE、中文、在地教練網絡）是護城河 |
| 使用者不願離開 LINE 群組 | 高 | **不要求離開**：PIKYOO 是 LINE 群組的外掛，而不是替代品 |
| 資料冷啟動失敗 | 中 | 一貼成局 + 開放資料 + 手動建置雙北 100 個場地 |

## 7. 修正後的 MVP

### 7.1 核心驗證問題
> 「一位團主願不願意用 PIKYOO 取代 LINE 接龍？一位新手能不能在 PIKYOO 5 分鐘內找到一堂體驗課或新手局？」

### 7.2 範圍（雙北先行）

```text
Auth
 └── LINE Login（Email 為備援）

Games 球局（核心）
 ├── 球局列表（地區 × 日期 × 程度 × 新手友善）
 ├── 球局詳情 + 報名 / 取消 / 自動候補
 ├── 建立球局（表單 + AI 一貼成局）
 └── 分享到 LINE（卡片 + 即時名單）

Learn 新手入口
 ├── 程度自評（3 分鐘問卷 → 建議 DUPR 區間）
 ├── 教練列表 / 教練頁
 └── 課程列表 / 課程詳情（詢問走 LINE）

Courts 球場
 ├── 列表 + 地圖（雙北約 100 處）
 └── 球場詳情（連結到原本的預約方式）

Me 我的
 ├── 個人檔案（程度、常打區域）
 ├── 我的球局（報名 / 開團）
 └── 出席紀錄（匹友信用 v0）
```

### 7.3 MVP 成功指標（上線 8 週內）
| 指標 | 目標〔假設〕 |
|---|---|
| 活躍團主（每週至少開 1 局） | 30 |
| 每週新增球局 | 100 |
| 球局滿團率 | ≥ 60% |
| 上架教練 | 30 |
| 課程詢問數 / 週 | 50 |
| 玩家 4 週留存 | ≥ 25% |

## 8. 開發路線圖（修正版）

| 階段 | 時間 | 內容 | 產出 |
|---|---|---|---|
| **Phase 0 — 驗證與基礎** | 第 1–2 週 | 20 場訪談（10 玩家 / 5 團主 / 5 教練）、商標網域、雙北場地資料建置、設計系統、**可點擊 Demo** | 訪談結論、Demo、資料庫 schema |
| **Phase 1 — MVP** | 第 3–8 週 | LINE Login、球局（含 AI 一貼成局、候補、LINE 分享）、新手入口、教練/課程目錄、球場目錄 | 雙北封測（邀請 10 位團主 + 10 位教練） |
| **Phase 1.5 — 公測** | 第 9–12 週 | 修正、匹友信用 v0、LINE 通知、SEO 內容 | 公開上線、KPI 追蹤 |
| **Phase 2 — 團主/教練工具** | 第 4–6 月 | 固定班底、週期開團、出席統計、教練排課、Pro 訂閱 | 第一筆收入 |
| **Phase 3 — 交易** | 第 6–9 月 | 第三方金流、課程線上報名付款、評價系統 | 課程手續費 |
| **Phase 4 — 生態** | 第 9 月後 | 擴展台中/高雄、賽事、DUPR 合作、品牌合作、企業團建 | 全台品牌 |

### AI 開發工作方式
- 每個功能先寫 **簡短 spec（使用者故事 + 驗收條件）** → AI 實作 → 人工 review → 自動化測試。
- 資料庫 schema 與 RLS 規則由人主導設計，這是最不能出錯的地方。
- 維持單一 repo（monorepo 不必要）、單一部署目標，降低 AI 上下文複雜度。

## 9. 技術架構（MVP）

```text
Frontend   Next.js (App Router) + TypeScript + Tailwind + PWA
LINE       LINE Login、LIFF、Messaging API（通知）
Backend    Supabase（Postgres + Auth + RLS + Storage + Edge Functions）
AI         LLM API：一貼成局解析、自然語言搜尋、程度自評建議
```
